# 空地协同项目整体框架与连接方法

本文面向项目交接、答辩说明和后续调试，按“系统框架、各模块实现方法、模块连接方法”总结当前仓库的整体架构。项目是 ROS Noetic / Gazebo 11 / catkin 工作空间，目标是实现 UAV 建图 + UGV 地形导航 + 机械臂抓取 + LLM 任务控制的空地协同系统。

> 仓库根目录：`Air-Ground-Collaborative-Manupulation`

---

## 1. 项目总体目标

项目核心思想是“无人机先看路，地面车再干活”：

1. UAV 在 Gazebo/PX4/MAVROS/EGO-Planner 下飞行，使用机载 LiDAR/深度相机扫描环境。
2. UAV 点云被转换到公共 `map` 坐标系，累积保存为 PCD，同时也可以实时发布给 UGV。
3. UGV 把 UAV PCD 或实时点云投影成 `/terrain_map`，作为 `move_base` 全局 costmap 的 static layer。
4. Husky + UR5 + Robotiq 2F-140 在 GPS/双 EKF 定位下做地形感知导航和抓取。
5. 室内任务侧可以通过 LLM Agent 把自然语言拆成导航、识别、抓取、放置等工具调用。

整体数据流：

```text
UAV 建图
PX4 SITL + MAVROS + EGO-Planner
        |
        v
LiDAR / depth cloud -> map frame point cloud
        |
        +--> /uav0/mapping/points_accumulated
        +--> ~/pointcloud_maps/uav_points_map_latest.pcd
        |
        v
UGV 地形投影
pcd_to_occupancy_map.py
        |
        +--> /terrain_map   (nav_msgs/OccupancyGrid)
        +--> /terrain_slope (坡度可视化)
        +--> /terrain_cloud (3D 彩色地形点云)
        |
        v
move_base global_costmap static_layer + local LiDAR obstacle_layer
        |
        v
/cmd_vel -> twist_mux -> husky_velocity_controller/cmd_vel
```

## 3. 三条核心运行链路

### 3.1 室外 UGV 单独地形导航链路

适合只验证 UGV 在 UAV 地图上跑地形导航。

启动方式：

```bash
source devel/setup.bash
roslaunch mobile_manipulator spawn_outdoor_city.launch

# 另一个终端
source devel/setup.bash
roslaunch mobile_manipulator ugv_terrain_nav.launch localization:=false use_sample_map:=true
```

连接关系：

```text
spawn_outdoor_city.launch
  -> Gazebo outdoor_city.world
  -> spawn Husky+UR5+2F-140
  -> robot_state_publisher
  -> controller_manager spawner
  -> ekf_localization       : odom -> base_link
  -> navsat_transform_node  : GPS -> odometry/gps
  -> ekf_global             : map -> odom
  -> twist_mux              : /cmd_vel -> husky_velocity_controller/cmd_vel

ugv_terrain_nav.launch
  -> laser_filter           : /front/scan -> /front/scan_filtered
  -> pcd_to_occupancy_map   : PCD -> /terrain_map /terrain_slope /terrain_cloud
  -> move_base              : /terrain_map + /front/scan_filtered -> /cmd_vel
  -> coordinate_align_checker
  -> RViz terrain_nav.rviz
```

关键文件：

| 文件 | 作用 |
|---|---|
| `src/mobile_manipulator/launch/spawn_outdoor_city.launch` | 启动 outdoor world、UGV、控制器、GPS/双 EKF |
| `src/mobile_manipulator/launch/ugv_terrain_nav.launch` | 启动地形投影、move_base、RViz、坐标检查 |
| `src/mobile_manipulator/scripts/pcd_to_occupancy_map.py` | UAV 点云/PCD 转地形占据图 |
| `src/mobile_manipulator/config/nav/terrain_layer.yaml` | 让 global costmap 的 StaticLayer 订阅 `/terrain_map` |
| `src/mobile_manipulator/config/nav/costmap_common.yaml` | footprint、inflation_layer、obstacle_layer 配置 |

### 3.3 UAV + UGV 同世界协同链路

入口脚本：

```bash
source devel/setup.bash
bash run_air_ground.sh
```

这个脚本故意用多个 `gnome-terminal` 分阶段启动，而不是一个 launch 全部并发启动。原因是 Gazebo、UGV 控制器、PX4 lockstep、MAVROS、EGO、move_base 都同时启动时容易出现控制器未接管、TF 时间戳混乱、机械臂垮下或日志难以排查。

启动顺序：

```text
1_Gazebo+UGV
  -> air_ground_world.launch spawn_uav:=false unpause_on_spawn:=false
  -> Gazebo paused
  -> UGV spawn + 控制器 + EKF

1.5_PX4+UAV
  -> px4_spawn_existing_gazebo.launch
  -> UAV 注入同一个 Gazebo world

unpause physics

2_MAVROS
  -> mavros/px4.launch

3_UAV_Stack
  -> forest_uav_mapping.launch
  -> EGO + 点云 + 建图 + UAV TF

4_UGV_Nav
  -> ugv_terrain_nav.launch localization:=false
  -> live_cloud_topic:=/uav0/mapping/points_accumulated

5_Takeoff
  -> px4_bridge.py

6_RViz
  -> air_ground.rviz
```

合并世界下的核心连接：

```text
UAV 点云实时长图:
/uav0/mapping/points_accumulated
        |
        v
pcd_to_occupancy_map.py (input_cloud_topic 非空，进入实时模式)
        |
        v
/terrain_map 周期更新
        |
        v
move_base global_costmap static_layer first_map_only=false
```

命名空间/话题隔离：

| 对象 | UGV | UAV |
|---|---|---|
| base frame | `base_link` | `uav_base_link` |
| 导航目标 | `/move_base_simple/goal` | `/uav/goal` |
| 控制输出 | `/cmd_vel` | EGO `/planning/pos_cmd` -> PX4 bridge |
| 定位链 | `map -> odom -> base_link` | `map -> uav_base_link` 或 MAVROS 局部 odom |

## 4. UGV 模块实现方法

### 4.1 机器人模型

主要文件：`src/mobile_manipulator/urdf/husky_ur5.urdf.xacro`

模型组成：

1. Husky 差速底盘。
2. SICK LMS1XX 前向激光，用于局部 costmap 障碍检测。
3. UR5 六自由度机械臂。
4. Robotiq 2F-140 夹爪。
5. Gazebo 插件：底盘控制、IMU/GPS、机械臂控制、抓取插件、真值/状态插件等。

TF 主链：

```text
map -> odom -> base_link -> ur5_base_link -> ... -> ur5_tool0 -> gripper
```

### 4.2 室外定位

实现文件：

| 文件 | 作用 |
|---|---|
| `src/mobile_manipulator/config/ekf_global.yaml` | global EKF，输出 `map -> odom` |
| `src/mobile_manipulator/config/navsat_transform.yaml` | GPS 经纬度转 map-frame odometry |
| `husky_control/config/localization.yaml` | local EKF，输出 `odom -> base_link` |

连接方式：

```text
wheel odom + IMU
        |
        v
ekf_localization
        |
        v
odom -> base_link

navsat/fix + IMU + odometry/filtered_map
        |
        v
navsat_transform_node
        |
        v
odometry/gps
        |
        v
ekf_global
        |
        v
map -> odom
```

注意点：

- `spawn_outdoor_city.launch` 中 local/global EKF 都开启 3D 姿态，避免坡上 LiDAR 投影错误。
- `ugv_terrain_nav.launch localization:=false` 用于复用已启动的 EKF，避免重复节点冲突。
- GPS datum 默认使用 `49.9, 8.9`，需要和 UAV PX4 home / Gazebo world GPS 参考一致。

### 4.3 地形投影与全局 costmap

主要节点：`src/mobile_manipulator/scripts/pcd_to_occupancy_map.py`

它有两种模式：

| 模式 | 触发条件 | 输入 | 输出 |
|---|---|---|---|
| 静态 PCD 模式 | `~input_cloud_topic` 为空 | `~pcd_file` | `/terrain_map`, `/terrain_slope`, `/terrain_cloud` |
| 实时点云模式 | `~input_cloud_topic` 非空 | `/uav0/mapping/points_accumulated` 等 | 周期重投影并重发 `/terrain_map` |

核心算法：

1. 读取 ASCII PCD 或 PointCloud2，获得 `x,y,z` 点。
2. 根据 GPS sidecar 或参数做坐标平移：
   - `datum_lat/datum_lon` 是 UGV 公共 datum。
   - `origin_file` 通常是 `~/pointcloud_maps/uav_map_origin.yaml`。
   - 节点用 `ll_to_utm()` 计算 UAV map 原点相对 datum 的米制偏移。
3. 用 `resolution` 建 2D grid。
4. 按每个 cell 的 z 统计去除低离群点。
5. 取每格最低点作为地面候选 DEM。
6. 对 DEM 填洞并做中值滤波，得到平滑地面 `ground`。
7. 计算地面坡度 `slope_deg`，用于可视化和可选软代价。
8. 用“高出本地地面 `obstacle_height` 以上的结构点”统计障碍：
   - 默认 `ugv_clearance=50.0`，近似表示高出地面的结构都保留为障碍，避免漏掉路灯、树干、指示牌。
   - `min_obstacle_points` 用于抗单点噪声。
9. 输出 OccupancyGrid：
   - `0`：可走地面。
   - `1..slope_cost_max`：可选坡度软代价。
   - `100`：致命障碍。
   - `-1`：未知。
10. 输出 `/terrain_cloud`，每个有效 cell 一个带 RGB 的 3D 点，用于 RViz 看真实地形高度。

连接到 `move_base`：

```text
/terrain_map
    |
    v
global_costmap/static_layer
    |
    +-- obstacle_layer: /front/scan_filtered
    +-- inflation_layer
    |
    v
navfn/NavfnROS -> DWAPlannerROS -> /cmd_vel
```

关键配置：

- `terrain_layer.yaml`
  - `map_topic: /terrain_map`
  - `first_map_only: false`，实时模式下允许更新。
  - `track_unknown_space: false`，UAV 未覆盖区域不直接阻断全局规划。
  - `trinary_costmap: false`，保留 1..99 软代价。
- `costmap_common.yaml`
  - `footprint` 用 Husky 实际矩形近似。
  - `obstacle_layer` 订阅 `/front/scan_filtered`。
  - `inflation_layer` 控制离障碍物距离。

### 4.4 局部避障

链路：

```text
/front/scan
    |
    v
laser_filters scan_to_scan_filter_chain
    |
    v
/front/scan_filtered
    |
    v
move_base local_costmap/obstacle_layer
```

实现意图：

- UAV 俯视点云可能漏掉低矮障碍或临时障碍。
- UGV 前向 LiDAR 用 local costmap 实时标记/清除障碍。
- `laser_filter_arm.yaml` 过滤机械臂/车体自反点，避免把自己标成障碍。

### 4.5 move_base 导航

主要配置：

| 文件 | 内容 |
|---|---|
| `config/nav/global_costmap.yaml` | 全局 costmap frame=`map`，插件包含 static/obstacle/inflation |
| `config/nav/local_costmap.yaml` | 局部 rolling window，frame=`odom` |
| `config/nav/dwa_local_planner.yaml` | DWA 速度、加速度、采样、评分参数 |
| `config/nav/terrain_layer.yaml` | 将 static map 改成 `/terrain_map` |

控制输出链：

```text
move_base
  /cmd_vel
    |
    v
twist_mux
  husky_velocity_controller/cmd_vel
    |
    v
Gazebo Husky 底盘
```

## 5. UAV 模块实现方法

### 5.1 PX4 + Gazebo + MAVROS

主要文件：

| 文件 | 作用 |
|---|---|
| `setup_uav.sh` | 安装 PX4、EGO-Planner、MAVROS 地理数据、依赖和补丁 |
| `one_key_takeoff.sh` | 单 UAV 建图的一键入口 |
| `src/uav_truth_tracker/launch/px4_spawn_existing_gazebo.launch` | 启动 PX4 SITL 并 spawn UAV SDF |
| `px4_bridge.py` | OFFBOARD 起飞和 setpoint 桥接 |

PX4 模型连接：

```text
Gazebo iris_depth_camera_lidar_mapping_light/model.sdf
        |
        v
PX4 SITL
        |
        v
MAVROS
        |
        +--> /mavros/local_position/odom
        +--> /mavros/local_position/pose
        +--> /mavros/imu/data
        +--> /mavros/global_position/global
```

关键点：

- 合并世界中 Gazebo physics 需要与 PX4 lockstep 匹配，当前脚本设置 `time_step=0.004`、`max_update_rate=250`。
- `PX4_HOME_LAT/PX4_HOME_LON` 必须和 UGV datum 一致，否则 UAV 点云和 UGV map 会产生巨大 GPS 偏移。

### 5.2 EGO-Planner 飞行规划

入口：`src/uav_truth_tracker/launch/forest_uav_mapping.launch`

输入：

- `/mavros/local_position/odom`
- `/depth/image_dilated`
- RViz 或全局规划器目标：`/move_base_simple/goal` 或 `/uav/goal`

输出：

- `/planning/pos_cmd`
- EGO 内部轨迹、B 样条规划结果

目标处理方式：

| 模式 | 节点 | 方法 |
|---|---|---|
| 高空俯扫 | `goal_elevator.py` | 直接把点击目标抬到 `flight_height` |
| 低空穿街 | `global_path_planner.py` | 从 UAV 累积点云构建 2D 障碍图，A* 生成绕楼子目标，再喂给 EGO |

EGO 的定位和目标坐标：

- 单 UAV 模式默认使用 MAVROS local frame。
- 合并世界中，用户在世界/UGV frame 点 UAV 目标，`global_path_planner.py` 可用 Gazebo 真值或 fallback offset 把目标换算到 UAV 局部 frame。

### 5.3 UAV 点云处理

入口：`src/uav_truth_tracker/launch/uav_points_to_ugv.launch`

处理步骤：

1. `pointcloud_to_pointcloud2_relay.py`
   - 把 Gazebo 原始 `sensor_msgs/PointCloud` 转为 `PointCloud2`。
   - 做 range filter，丢弃最大距离边界壳。
   - 做 UAV 自身机体/旋翼过滤。
   - 做稀疏离群过滤和可选体素降采样。
2. `uav_pointcloud_to_world.py`
   - 使用 TF 把点云从 `uav0/velodyne_link` 投影到 `map`。
   - 可使用 latest TF fallback，避免时间戳轻微错位导致整帧丢弃。
3. `uav_truth_cloud_projector.py`
   - 合并世界可选真值投影器。
   - 直接从 Gazebo model state 推导 UAV 位姿，不依赖 MAVROS TF 时间戳。
4. `uav_pointcloud_map_recorder.py`
   - 将 map frame 点云按 voxel 累积。
   - 发布 `/uav0/mapping/points_accumulated`。
   - 定时或服务触发保存 PCD。

保存服务：

```bash
rosservice call /uav_pointcloud_map_recorder/save "{}"
```

输出文件：

```text
~/pointcloud_maps/uav_points_map_latest.pcd
~/pointcloud_maps/uav_points_map_YYYYMMDD_HHMMSS.pcd
~/pointcloud_maps/uav_map_origin.yaml
```

### 5.4 UAV/UGV 坐标对齐

项目里有两类对齐：

1. GPS/UTM 对齐，用于静态 PCD：

```text
UAV 建图时:
uav_map_origin_saver.py
  /mavros/global_position/global -> ~/pointcloud_maps/uav_map_origin.yaml

UGV 导航时:
pcd_to_occupancy_map.py
  datum_lat/datum_lon + origin_file -> UTM offset -> 平移 PCD
```

2. 合并世界实时点云对齐：

```text
UAV points_accumulated 在 UAV/MAVROS 局部系
        |
        v
pcd_to_occupancy_map.py auto_align 或 offset_x/y
        |
        v
投影到 UGV/world/map frame
```

检查节点：`coordinate_align_checker.py`

- 比较 UAV GPS 与 UGV GPS。
- 如果 datum 不一致，会出现公里级偏差。
- 合并世界中两机真实物理间距可能几十米，所以 `run_air_ground.sh` 会放大 warn threshold，避免误报。

## 6. 机械臂、感知与抓取模块

### 6.1 MoveIt

主要包：`src/husky_ur5_moveit_config/`

核心组件：

- planning group：`ur5_arm`
- gripper group：代码中使用 `hand_e_gripper`，实际模型为 Robotiq 2F-140，需要以当前 MoveIt 配置为准。
- planner：OMPL / RRTConnect。
- OctoMap：用于抓取路径避障。
- RViz：`moveit_rviz.launch`。

启动方式见 `bringup.sh`：

```text
roslaunch husky_ur5_moveit_config move_group.launch
roslaunch husky_ur5_moveit_config moveit_rviz.launch
```

### 6.2 YOLO + 深度定位

YOLO 节点：`src/mobile_manipulator/src/trt_yolo_node.cc`

接口：

```text
Service: /yolo/detect
Type: mobile_manipulator/DetectObjects

Request:
  sensor_msgs/Image image

Response:
  Detection[] detections
  sensor_msgs/Image annotated_image
  float32 inference_time_ms
```

检测结果 msg：`src/mobile_manipulator/msg/Detection.msg`

典型链路：

```text
/camera/color/image_raw
        |
        v
/yolo/detect
        |
        v
Detection(center_u, center_v, width, class_name, confidence)
        |
        v
MasterControl.get_3d_coordinates()
        |
        +-- /camera/color/camera_info
        +-- /camera/depth/image_raw
        +-- TF: realsense_camera_optical_frame -> ur5_base_link
        |
        v
object PoseStamped in ur5_base_link
```

### 6.3 MasterControl 动作层

主要文件：`src/mobile_manipulator/src/mobile_manipulator/master_control.py`

它是物理执行 API，屏蔽底层 ROS 细节。主要能力：

| 方法 | 实现 |
|---|---|
| `move_base_to(x, y, yaw)` | 通过 `move_base` action 发送 `MoveBaseGoal` |
| `get_current_pose()` | TF 查询 `map -> base_link` |
| `scan_with_arm(target_class)` | UR5 扫描多个关节位，同时循环调用 `/yolo/detect` |
| `get_3d_coordinates(u,v,w)` | 深度图反投影 + TF 到 `ur5_base_link` |
| `execute_pick()` | GPD 抓取优先，失败则启发式水平抓取 |
| `execute_place()` | 机械臂移动到目标位置并打开夹爪 |

抓取流程：

```text
Agent / test node
        |
        v
MasterControl.scan_with_arm()
        |
        +-- UR5 按 SCAN_JOINT_CONFIGS 扫视
        +-- YOLO 连续检测目标类别
        |
        v
MasterControl.get_3d_coordinates()
        |
        v
MasterControl.execute_pick()
        |
        +-- 可选 GPD: /gpd_cloud -> /clustered_grasps
        +-- 更新 MoveIt OctoMap
        +-- 打开夹爪
        +-- 到 pre-grasp
        +-- 插入到 grasp_pose
        +-- 闭合夹爪
        +-- 抬起/回 ready pose
```

## 11. 常见连接问题定位

| 现象 | 优先检查 |
|---|---|
| `/terrain_map` 没有发布 | `pcd_to_occupancy_map` 日志、`pcd_file` 是否存在、静态模式是否 fatal 退出 |
| RViz 看不到地形 | Fixed Frame 是否为 `map`，显示项是否订阅 `/terrain_cloud` 或 `/terrain_map` |
| UGV 不动 | `/move_base/status`、`/cmd_vel`、`twist_mux`、local costmap 是否被自身激光堵住 |
| UGV 地图和车不对齐 | `datum_lat/lon`、`PX4_HOME_LAT/LON`、`uav_map_origin.yaml` |
| UAV 点云只堆在一处 | 检查 `use_truth_tf/use_truth_projector`、TF 时间戳、`/mavros/local_position/odom` 是否更新 |
| EGO 报 terminal in obstacle | 目标是否超出 map_size，低空目标线是否穿楼，`ground_filter_margin` 是否合适 |
| 合并世界 TF 冲突 | UAV 是否使用 `uav_base_link`，UGV 是否仍使用 `base_link` |
| Agent 找不到 semantic map | 检查 `agent.py` 和 `flask_ui.py` 中是否仍指向 `~/learning_ws` |
| YOLO 服务不可用 | `rosrun mobile_manipulator trt_yolo_node` 是否启动，TensorRT engine 是否构建成功 |
| MoveIt 抓取失败 | `/clear_octomap`、相机 TF、深度图、GPD `/clustered_grasps`、规划组名称 |

## 12. 当前架构特点与限制

特点：

1. 空地两端使用统一 `map` frame 和 GPS datum，便于 UAV 地图直接给 UGV 用。
2. UGV 地形导航使用原生 `move_base`，通过 `/terrain_map` 接入 static layer，工程上简单稳定。
3. UAV 点云既支持离线 PCD，也支持实时 `/points_accumulated` 重投影。
4. LLM 只负责决策和工具调用，底层动作由 `MasterControl` 明确执行，边界清楚。
5. 合并世界通过分阶段启动和 frame/topic 隔离解决多机器人冲突。

限制：

1. EGO-Planner 本质是局部规划器，低空绕大建筑依赖额外 `global_path_planner.py`，仍不是完整覆盖式建图。
2. UAV 俯扫对树冠/楼顶很强，但对侧面和遮挡下方结构可能缺失。
3. `/terrain_map` 是 2D/2.5D 表达，不能表达完整 3D 可通行空间。
4. Agent/Web UI 还有老路径假设，迁移工作空间时需要修正。
5. 真机 UAV/UGV 接入尚需重新验证传感器 topic、GPS datum、TF 和时钟。
